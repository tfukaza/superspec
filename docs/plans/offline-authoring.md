# Offline material and item authoring ownership

These decisions precede moving the maintained Rust generators out of the CLI.
This is an ownership cleanup, with no performance work or generated-asset change.

MaterialSpec owns channel accumulation/encoding, reusable image refinement and
resampling, periodic sampling helpers, and the existing intrinsic material recipe
implementation under an explicit authoring/content module. Kowloon owns its kit,
lettering, prop textures, stock shapes, atlas conventions and catalog transforms.
Shared catalog definitions remain independent of their authoring tools.

Portable generator functions consume decoded images, JSON, supplied fonts or a caller
supplied asset reader for dynamically referenced inputs. They produce named image
and catalog outputs. The CLI retains arguments, filesystem roots, input loading,
directory and overwrite policies, writing, font downloads and font-cache updates.
No implementation library acquires a native filesystem or network dependency.

Offline-only FFT, font and glyph-rasterizer dependencies are enabled by an explicit
compiler `authoring` feature used by the material CLI. The existing runtime and
Wasm compiler do not enable it. Algorithms, source order, filenames, pixel/channel
rounding, geometry layout and error checks remain unchanged during the move.

No standalone generator integration tests existed at this boundary. Verification
adds focused process and library tests, compares selected generated bytes against
the frozen implementation using the same inputs, checks the ordinary runtime
without authoring enabled, and independently reviews the ownership and host-adapter
split. Published catalogs and image assets are not regenerated as part of this cleanup.

## Implemented boundaries

| Owner | Operations |
| --- | --- |
| `materialspec::authoring` | Map accumulation and encoding, periodic fields, concrete/timber/brushed-metal recipes, resampling and photo-derived channels |
| `itemspec::embedded_images` | Supported single-material GLB image extraction, with an output callback preserving channel-order publication and deletion |
| `worldspec::themes::kowloon::authoring` | Kitchen/vent/restaurant materials, kit and lettering rendering, prop atlases, stock geometry, atlas packing and catalog transforms |
| `worldspec::themes::site_textures` | The existing clay/chalk/night texture collections |
| Material CLI | Command parsing, source roots, file access, directory/exclusive-file publication, font acquisition and atomic font-cache updates |

The theme's `Inputs` supplies read, existence and catalog callbacks. These preserve
the former lazy source-resolution order and permit memory-backed authoring without
a source checkout. Native publication still uses the former overwrite/create-new
rules. FFT and glyph rasterization dependencies are optional compiler authoring
dependencies; the native font host retains its font parsing dependency to validate
downloads before cache publication.

## Correctness evidence

`material_authoring` passed all five tests. Eight output SHA-256 hashes match the
pre-move executable: three brushed-metal maps, bag-cluster geometry, and three food
atlas maps plus their catalog. Tests also cover occupied output, missing/invalid
inputs, recovery, exact memory-source read order, corrupt-image recovery, font
capacity checks before acquisition, loader failure and GLB per-channel partial
publication followed by recovery. Font pixels were reviewed as unchanged source;
the tests do not download fonts or claim a newly rendered lettering comparison.

The independent review compared 150 unchanged normalized function bodies and
reviewed the changed input/publication adapters. CLI checks and tests compile
without warnings. The ordinary Wasm feature graph excludes the optional FFT/font
authoring dependencies.
